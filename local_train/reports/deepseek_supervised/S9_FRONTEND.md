# S9 — Russian Frontend: модуль + benchmark + проба v1.0 (19.09.2026)

## Что сделано
1. **`src/auk/infer/ru_frontend.py`** — конвейер `raw text → to_speakable()`:
   rutextnorm.normalize_russian (числа/даты/валюты/телефоны/единицы/аббревиатуры)
   → `_accentize_ru` (RUAccent + pron-лексикон) → опц. ru_to_latin.
   Диагностика: `flag_uncertain()` (span'ы, которые правила не разрешили).

   зафиксированы в FRONTEND_BENCH.md как известные ограничения).

## S9.2 — форма аббревиатур + нормализация WER (итоги)

1. **abbr_form_probe** (16 генераций, s7@5750): МГУ — dots лучшая форма (heard «мгу им
   ломоносова» стабильно на обоих сидах, WER 0.50/0.62), spaces сливается в «мг уим»,
   raw → «мангу». ООО проваливается в ЛЮБОЙ форме (0.75–1.0) — ограничение модели.
   `_ABBR` переключён на точечную форму (v4 probe подтверждает: fb_100 heard «ооо ромашка
   ип иванов и» — произнесение верное, WER-артефакт).
2. **`wer_norm.py`** — нормализация expected/heard (коллапс побуквенных цепочек «о.о.о.»→«ооо»,
   ё→е, снятие «+», пунктуации): убирает ASR-артефакт на аббревиатурах. Unit-тесты 5/5.
   `frontend_probe.py` теперь пишет wer_norm + cer_norm; гейты считаются по wer_norm.
3. **v4 probe с wer_norm (33 текста)**: wer_mean **0.255** (v1 0.319 → v4 0.255);
   abbr_name 0.489→0.370; long_word_cluster CER: fb_180 0.061, fb_181 0.154, fb_182 0.000 —
   2/3 «провалов» категории были чистым артефактом WER; реальная поломка — fb_181
   «рентгеноэлектрокардиографический» (CER 0.154, модель переставляет морфемы — кандидат
   в S8-микс как long-word hard case).

**ВЫВОД S9 (ПРОВЕРЕНО):** фронт-конвейер (rutextnorm + tech-prespell + abbr-dots +
safe_accentize + wer_norm) снижает hard-benchmark WER с 0.319 до 0.255; числовые категории
в гейтах (money 0.083, number 0.122, units 0.150, date 0.075, phone 0.111, mined 0.000).
Остаточные проблемы — модельного уровня (ООО в любой форме, code_switch 0.55, сверхдлинные
составные слова) и требуют либо лексикона-стиля, либо данных в миксе (S8/S10).

## S9.2 — план (следующий шаг фронта, без весов)
- pron-лексикон техно-замен: «ООО»→«о о о», «МГУ»→«эм гэ у», «ИП»→«индивидуальный
  предприниматель», «README»→«ридми», «npm»→«энпм», латинские термины → русская передача
  («задеплой»→«разверни» — опциональный стиль-слой);
- long_word_cluster — ПРОВЕРЕНО глазами (v2 probe): WER завышен метрикой. fb_182 heard
  «частно предпринимательская» = произнесено ВЕРНО, просто ASR разделил составное слово
  (WER 1.0 — артефакт токенизации); fb_180 — вставка «его» (мелочь); fb_181 — реальный
  провал («рентгеноэлектрокардиографический» → «рентгеновая электрокардиографичестика»).
  Реальная доля поломок в категории ≈1/3, не 3/3. Для гейта считать CER или нормализовывать
  дефисы/пробелы перед WER.

## Находки (ПРОВЕРЕНО на аудио)
1. **Баг фонетического респеллинга**: `_accentize_ru` (RUAccent) иногда выдаёт
   фонетическую орфографию вместо словоформы — «Встреча» → «Фстреча» (оглушение).
   Модель AuK-ru обучена на ОРФОГРАФИЧЕСКОМ тексте и такое деградирует (fb_020:
   heard «встреча двадцать первое синский...»). Для AuK-ru accentize должен ТОЛЬКО
   добавлять маркеры «+», не заменяя буквы. **TODO S9.1**: фильтр/отключение
   девойсинг-респеллинга (проверять, что normalize→accentize сохраняет состав букв).
2. **Техно-домен вне покрытия**: URL/email/версии/латинские аббревиатуры нужно
   либо проговаривать русскими словами («сайт пример точка ком»), либо не читать
   вовсе. Кандидат на таблицу замен в pron-лексиконе (`pron_lexicon.json`).
3. **Телефоны**: дефисные группы лучше разбивать на отдельные цифры с паузами или
   читать «восемь-восемьсот» как «восемь восемьсот» (без дефиса в тексте фронта).
