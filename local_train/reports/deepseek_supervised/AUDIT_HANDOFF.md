# AUDIT_HANDOFF — аудит AuK/s2 и передача (16.09.2026)

Исполнитель: внешний аудит (DeepSeek). Метод: проверка фактических артефактов и скриптов,
повторный мерж, объективные замеры, проверка автосудьи на controls. Выводы — только там, где
есть носитель доказательства. Всё, что «из текста отчётов», помечено как непроверенное.

## 1. Что сделано в этом аудите

- Инвентаризация s2: адаптеры, merged-веса, `run_params.json`, manifest'ы, logs, данные.
- **Повторный мерж s2-адаптеров** (A/B × 250/500) с базой `auk_ru_10000` и сверка хэшей.
- Переписана автосудья Gemini: `audit_gemini_judge_v2.py` (task-specific рубрики, routing аудио,
  raw+hashes, schema/audio_access-валидация, no_result, ретраи, resume).
- Собран preflight (12 реальных задач + 5 controls с positive/negative manipulation) и проверена
  чувствительность судьи — `PREFLIGHT.md`.
- Зафиксировано реальное состояние проекта — `STATUS.md`; правила приёмки — `acceptance_protocol.md`.
- v1-результаты Gemini (41 строка) изолированы как exploratory: `exploratory/results_audit_gemini.v1.jsonl`.

## 2. Воспроизводимость весов (закрыто)

Изначально merged-файлы s2 отсутствовали, и эвалы A/B были невоспроизводимы. Выполнен мерж:

```
merge_lora.py --run_dir run_s2_{A,B} --ckpt model_{250,500}.pt
  --out run_s2_{A,B}/merged/auk_s2_{A,B}_{250,500}.safetensors
  --base_ckpt run_ru_s1/merged/auk_ru_10000.safetensors --lora_r 32 --lora_alpha 64
```

`sha16` (первые 2048 МБ) всех четырёх файлов **совпал** с записанным в `run_params.json`:
A@250 `c17d3b62e895feff`, A@500 `f1bc15582c227b1a`, B@250 `b9a064fcb6d0b28e`,
B@500 `10cdd9872b0235ea`. **Это доказывает только префикс 2 ГБ, а не побитовую идентичность
всего 6-ГБ файла** (оригиналы потеряны, исторический полный хэш неизвестен). Полные sha256
восстановленных файлов зафиксированы в `full_sha256.json`.

## 3. Автосудья: статус валидации

- v2 использует task-specific промпты (tool op / capability), два аудио только когда задача
  реально требует вход, референс для `voice_similarity_to_ref`, `no_result` при отсутствии входа.
- Preflight: positive control `text_fidelity=10`; отрицательные (тишина, обрыв, шум, подмена
  текста) — `overall` 0-2. Судья различает испорченные примеры и не выдумывает успех.
- Сохраняются: полный raw (отдельный файл), SHA256 всех аудио, `prompt_version`+`prompt_sha256`,
  model alias, seconds; невалидный JSON не считается успехом.
- Ограничение: preflight — один слепой сэмпл на задачу. Никаких выводов о вариантах из preflight.

## 5. Ключевые факты и риски

- **Веса:** восстановлены и подтверждены (см. §2). s1 release candidate — u18000; u22000 не победитель.
- **Метрики `COMPARISON.md`:** u10000 TTS WER 1.04 → A@500 0.40, B@500 0.19; утечки рефа
  37 → 9-12. По содержанию B@500 лучший, но фонетика/естественность не измерены.
- **Measurement gap:** recall в `src/auk/infer/quality.py` считает уникальные слова в знаменателе
  (recall>1, неверный ответ = 1.0) — исторические best-of-N ранги недостоверны.
- **Инструменты:** авто-метрики не проверяют выполнение операции; magnitude volume/speed/pitch
  требует DSP (dB/полутона), судья даёт только направление/качество.
- **Данные:** `data_s2_full\v2_after_identity` 17 503/65; B_mix 21 879; `accounting.json` A 680/0,
  B 526/138 совпадает с `compare.json`.
- **Логи обучения** лежат вне репозитория (`G:\AI\_tmp\s2_A.log`, UTF-16). В репо не хранятся.
- **v1 Gemini** сохранён как exploratory и в решениях не используется.

## 6. Чего НЕ делать по итогам

- Не объявлять A/B/u10000/любой s2-вариант победителем на авто-сигнале.
- Не использовать preflight-оценки как метрику варианта (это проверка судьи).
- Не считать `ckpt_sha16` полным хэшем и не сравнивать его с полным sha256.
- Не выдавать частичный sha256 за доказательство побитовой идентичности всего файла.
- Ручное слепое прослушивание — ОПЦИОНАЛЬНОЕ подтверждение, а не обязательный блокер
  (пользователь авторизовал DeepSeek как аудитора; слух не является требованием фазы).
