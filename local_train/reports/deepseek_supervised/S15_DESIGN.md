# S15 DESIGN — Adapter Architecture (проект; реализация после S12/S13)

## Проблема
Каждый этап сейчас выпускает монолит 6.12 ГБ (merged safetensors). Цепочка s0→s10 уже
заняла ~55 ГБ локально; на HF — 4 монолита (24.5 ГБ). Комбинации навыков невозможны
(эмоции s7 и neutral s5 — разные файлы, нельзя «взять лучшее из обоих»).

## Целевая архитектура
```
AuK-ru Core (база u10000, одна копия 5.84 ГБ)
├── adapter: neutral      (s5-ветвь, LoRA r32/α64, ~590 МБ)
├── adapter: emotion      (s7@5750, ~590 МБ)
├── adapter: whisper      (S12, speaking_mode)
├── adapter: character    (будущее)
└── adapter: experimental
```
API: `model.load_adapter("emotion")` / горячая замена без перезагрузки базы.

## Техническая основа (уже есть)
- Все стадии s2+ обучены от ОДНОЙ базы auk_ru_10000 (LINEAGE) → адаптеры взаимозаменяемы;
- train.py уже грузит peft-адаптер отдельно от базы (resume-логика) — инференс-загрузчик
  «база + adapter.pt» — маленький шаг;
- merge_lora.py доказал совместимость r32/α64 по всей цепочке.

## Композиция адаптеров (исследовательская часть)
1. **Простое переключение**: AukInfer(ckpt=base, adapter=X) — минимум реализации.
2. **LoRA-мержинг весов**: W = W_base + α·ΔW_emotion + β·ΔW_neutral — проверить на гейтах,
   даст ли комбинация (эмоции s7 + neutral s5) результат лучше каждого по отдельности.
   Это прямой ответ на «S7 trade-off»: вместо выбора канон-чекпойнта — композиция.
3. **Маршрутизация по инструкции**: emotion-инструкция → emotion-адаптер, нейтральная →
   neutral (в рантайме, до generate).

## План работ (оценка)
- Этап 1 (0.5 дня): `adapter_infer.py` — загрузка базы + адаптер.pt (peft), smoke на s7/s5;
- Этап 2 (1 день): LoRA-мержинг α/β сетка {0.25,0.5,0.75,1.0}² → 16 комбинаций →
  короткий гейт (60 эмо + 48 tts) → лучшая комбинация;
- Этап 3 (0.5 дня): публикация HF-репо в формате «core + adapters» (экономия ~18 ГБ на HF),
  миграция model card; v1.x релизы = версии адаптеров, не весов.

## Риски
- peft-версии/конфиги должны совпадать (r32/α64/dropout 0.05 — у всех стадий совпадают, ПРОВЕРЕНО по train-логам);
- LoRA-мержинг двух адаптеров одной базы математически корректен (линейность), но качество —
  эмпирический вопрос (может быть интерференция в общих модулях to_qkv/ff).

## Gate S15
- adapter-инференс ≡ merged-инференс (побайтово или WER/sim-паритет на 20 сэмплах);
- лучшая композиция ≥ v1.0 по эмо-гейту (48.3%) И ≥ s5 по neutral clone judge (8.20) —
  если достигнуто, это и есть «s5+s7 в одном» — главная нерешённая trade-off проекта.
