# S17 DESIGN — Frontend v2 (проект; запуск после S16 human-gate)

## Что осталось незакрытым в S9 (ПРОВЕРЕНО пробами v1→v4)

| проблема | статус после S9 | причина |
|---|---|---|
| числа/даты/телефоны | ✅ решено (0.075–0.122) | rutextnorm + tech-prespell |
| URL/email | ✅ снижено до 0.368 | «сайт X точка ком» |
| аббревиатуры | ⚠️ частично (0.37–0.45) | точечная форма помогает (м.г.у.), но ООО проваливается в любой форме |
| code-switch (RU/EN) | ❌ 0.550 | «задеплой/пулл реквест» — модель не знает англо-сленг; фронт не помогает |
| сверхдлинные слова | ❌ (1 реальный провал из 3) | «рентгеноэлектрокардиографический» → морфемный распад |
| naturalness/prosody | ❌ 5.2–5.4 на hard | модельный уровень, не фронт |

## Frontend v2 — что МОЖЕТ улучшить фронт (без весов)

1. **Морфемная разметка сверхдлинных слов — ОПРОВЕРГНУТА пробой (21.09 00:05)**.
   `s17_longword_probe.py`: 6 кейсов × {plain, hyphen} × 2 сида = 24 генерации на v1.0.
   **Hyphen выигрывает 1/6** (case 4 «четырехсот-двадцати-пяти-летний» 1.75→1.50),
   проигрывает 2/6 (case 3 «суб-стан-ти-ви-ро-ва-нии» 0.62→0.88, case 1 1.00→1.25),
   ничья 3/6. Вывод: дефисная морфемная разметка НЕ внедряется.
2. **WER — невалидная метрика для длинных слов; правильный показатель CER.**
   Те же пробы: case 1 WER 1.00 при **CER 0.01** (heard «частно предпринимательская
   деятельность» — произнесено ВЕРНО, ASR лишь разделил составное слово пробелом);
   case 0 WER 0.75 при CER 0.06; case 5 WER 0.00/CER 0.00. Т.е. значительная часть
   «провала long_word_cluster» (WER 0.75 в S9-пробах) — артефакт токенизации GigaAM,
   а не дефект произношения. Реальных провалов в категории ≈1 из 6 (case 3
   «распорядился о субстантивировании» → «распалия диллиса», CER 0.13).
   → Все фонетические гейты переводить на **CER + human**, WER оставить как вспомогательный.
3. **Лексикон code-switch**: таблица частых англицизмов → русская передача
   (деплой → «разверни»/«деплой» с ударением, пул реквест → «пул-риквест»,
   фича → «фича»). Спорно: меняет слова пользователя — только с флагом --adapt-loanwords.
4. **Расширение омографов**: RUAccent turbo2 покрывает основные; добавить ручной
   словарь ~100 спорных форм. ВНИМАНИЕ: hard_eval_v1 заморожен — словарь строить по
   ВНЕШНИМ источникам (словари gramota.ru и т.п.), а не по бенчмарку, иначе гейт обесценится.
5. **Ё-нормализация**: «все» vs «всё» — проверить, что цепочка rutextnorm→accentize не теряет ё.

## Что НЕ делает frontend v2
- Не чинит naturalness/prosody (это S16/веса);
- Не трогает frozen-бенчмарк;
- Не добавляет LLM-нормализацию (детерминированность — принцип S9).

## Gate frontend v2
- hard-бенчмарк (frontend_probe на hard_eval_v1_clean, 33 текста): wer_norm ≤ 0.24
  (сейчас 0.255 у v1.0; у s16 будет свой замер);
- long_word CER ≤ 0.05 (сейчас 0.154 на провальном кейсе);
- регресс-прогон: все S9-гейты остаются зелёными (date ≤0.20, phone ≤0.30, money ≤0.10).

## Порядок (по ROADMAP после S16)
S16 human-gate → reranker calibration (веса composite по human-флагам) → **frontend v2** →
first-shot reliability (S10-v2).
